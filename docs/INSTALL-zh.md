# CampusQuest 安装与验证说明(APK 0.4.2)

## 装到手机(红魔 6 Pro)
1. 把 **`CampusQuest-0.4.2.apk`**(最新)传到手机,直接覆盖安装,**数据保留**(不用卸载)。
2. 文件管理器点开 APK → 允许「安装未知应用」→ 安装。

> 签名证书与 0.2.2~0.4.1 完全一致(SHA-256 `e41194a3…2937`),
> 并且这份签名 keystore 已经钉进工程(`keystore/cq-release.keystore`),
> 以后无论在哪台机器打包,都能覆盖安装,不会再出现「必须先卸载」的情况。

## 0.4.2 更新:修浅色灰框 / 小组件外观可选

### 1)浅色模式「课表四周一圈灰框、页面底部有动态灰框」
- 真凶不是背景,是**面板自己的投影**:`Modifier.shadow(14.dp)` 画在填充**下面**,
  而面板填充是 44% 白的半透明色 `0x70FFFFFF` —— 阴影从半透明填充里透出来,
  在浅色底上就是一圈灰边,滚动时它跟着面板移动,看起来像「动态灰框」。
- 0.4.0 之前这一圈被整层噪点(`Multiply .42`)盖住了,0.4.1 把噪点删掉,它就暴露了。
- **修法**:课表面板、任务面板的 `.shadow(...)` 整行删除,只留 `clip + 半透明白底 + 1dp 亮边`;
  玻璃质感靠这道亮边表达,不再靠阴影。
- 定量验证(同一行像素):修前 面板外侧 (243,238,228) → 内侧灰带 (214~224,…) → 面板 (249,246,240);
  修后 (243,238,228) → (248,246,240),灰带消失。

### 2)小组件外观:跟随系统 / 浅色 / 深色 / 彩虹
设置 → 校历设置 → **小组件外观**,四选一,点完立即刷新桌面上所有尺寸的小组件:

| 选项 | 效果 |
|---|---|
| 跟随系统 | 原来那套(深色系统=深色卡片),默认值 |
| 浅色 | 固定奶油纸面 + 深字,系统切深色也不变 |
| 深色 | 固定 `#16161C` 碳黑卡面 + 亮字,沿用 App 深色主题的配色 |
| 彩虹 | 两种角度的线性渐变叠一层薄雾(135° 蓝→紫→橙,45° 半透明青→白→黄),「把彩虹搅匀」的柔光感;课程小卡是磨砂白 |

- 实现:风格存在独立 `SharedPreferences("cq_widget")`,**不走** Room/DataStore
  (小组件是 BroadcastReceiver,必须同步读);
- 换主题时逐行重刷字色,保证新增的第三行/第六行不会残留 XML 里的深色字。

## 0.4.1 更新:修乱码 / 修深色灰块 / 小组件信息量

### 1)「屏幕上时不时跳出的白色乱码汉字」——找到最可能的元凶并移除
这次把所有绘制链路翻了一遍,可疑项集中在三处,**全部清掉**:

| 原实现 | 为什么会花 | 现在的做法 |
|---|---|---|
| 支线任务的「题记」用 **Serif 衬线 + 斜体** | 中文字体包里没有衬线/斜体字形时,系统要**合成斜体 + 回退字体**;部分 ROM(含红魔)在滚动时会把整行合成成一团认不出的字 —— 位置正好在卡片中左侧、颜色偏白 | 改成**默认字体 + 正体**:字形直接取系统黑体,不再合成 |
| 背景层:26 秒无限动画平移整层 + 160px 噪点 `ImageShader` + `BlendMode.Overlay/Multiply` | 高级混合模式要求 Skia 整块离屏保存回读,叠加每帧移动的全屏图层,Adreno 上会把字形图集弄花 | 背景改成**一次静态绘制**:底层实色 + 几个径向光斑。**没有动画、没有平铺 shader、没有混合模式** |
| 置顶灯带:每帧 `new Brush.horizontalGradient(色标数组)` | 每帧新建一个 Skia 着色器,长时间跑同样伤字形缓存 | 渐变 **只创建一次**,动画只改画布平移量(视觉上照样是流动的 RGB 灯带) |

另外顺手去掉了几处「深色下会变成灰雾」的投影:深色模式下面板/新增按钮不再画黑色大阴影,
课程名前面的小色点也不再挂彩色 spot 投影。

> 说明:模拟器是软件渲染 + x86,复现不了这台机器的 GPU 字形问题;
> 上述三处是代码里仅有的「高级绘制路径」,已全部移除。若仍偶发,请拍一张屏保级截图给我。

### 2)深色模式「背景上灰色色块随滚动变动」
- 深色背景的四个彩色光斑 alpha 由 0x59/0x4A/0x38/0x2B **降到 0x3D/0x33/0x28/0x1E**,
  不再透过半透明面板把卡片染成紫/粉;
- 面板、新增胶囊在深色下**取消黑色投影**(阴影落在暗底上就是一块会随内容移动的灰斑);
- 背景层不再有任何动画,滚动时背景绝对静止。

### 3)小组件「只显示几个字、看不清、显示太少」
- **4×1**:去掉中间那枚「剩 N 天」胶囊,标题宽度从约 2 个字恢复到 7 个字(实测「英语六级口语考试」完整显示);紧急度改用左侧圆圈颜色表达(红=逾期/今天,橙=48h 内,灰=其余)。
- **4×2**:**今天没课时右列整块让给待办** —— 隐藏分隔线和右栏,列表从 3 条变 4 条,标题宽度翻倍;
  有课时仍是「左 3 条待办 + 右今日课表」。
- **4×4**:每组从 2 行扩到 **3 行**(逾期/两天内/稍后各 3 行,最多 9 条),
  填满原来下半截的空白;今日课表与周进度条仍压在底部。

## 0.4.0 更新:六种桌面小组件

设置(⚙ 右上角)最下面多了「桌面小组件」一段,点尺寸 → 系统弹「要添加到桌面吗」→ 添加;
之后长按桌面上的小组件可拖动位置/调整(部分桌面支持)。

| 尺寸 | 名字 | 长什么样 |
|---|---|---|
| **2×1** | 极简条 | 只有一件最急的事 + 倒计时胶囊。桌面很挤时的默认尺寸 |
| **2×2** | 小三件 | 三件最急的待办 + 底部一行「下一节 10:00 模拟电子技术」 |
| **4×1** | 今日横条 | 左「10/21 · 第 7 周」/ 中「最该做的事」/ 右「下一节课」,三段固定宽度 |
| **4×2** | 待办+今日课 | 左三件待办(带逾期/剩 N 时),右「今天还要上」四节课 + 教室(**最推荐**) |
| **4×4** | 完整面板 | 分组待办(逾期 / 两天内 / 本周)+ 今日课表 + 底部学期周进度条 |
| **5×4** | 双栏桌面 | 左六件待办 / 右课程表 + 周进度,给平板、折叠屏、大屏用 |

### 排序与显示规则(六个尺寸一致)
**待办优先,课表次之。** 具体顺序:置顶插队 → 逾期 → 今天到期 → 48 小时内 → 更远 → 不限时间。

### 点哪里会发生什么
- **点左边那个圆圈 ○** → 直接把这件待办标记完成(小组件立刻刷新,待办数 -1)。
- **点这一行的正文** → 打开 App 并跳到对应页签(课程作业 / 支线任务)。
- **点空白处** → 打开 App。
- 课程行、日期块、下一节那一段 → 都指向课表。

### 深浅色与刷新
- 小组件跟随**系统**深色模式(`values-night` 资源),和 App 里手动切的主题互不影响。
- 数据一变(在 App 里加/删/完成任务、导入课表、改开学日期)小组件会自动重画;
  另外每 30 分钟系统也会兜底刷新一次。
- 点圆圈完成之后,如果想撤销,进 App 在「已完成」分组里取消勾选即可。

### 已知差异(和 App 内视觉的差别)
- 小组件用的是 **RemoteViews**,没有毛玻璃、噪点、渐变流动 —— 这些系统不支持。
  所以卡片是**实色纸面 + 1dp 描边**(浅色 `#FBF7EE`,深色 `#16161C`),圆角、色条、字体层级照旧。
- 课程色条、圆点、倒计时胶囊的配色和 App 里完全一致(同一套 `cq_w_*` 颜色)。
- **5×4 在 4 列的手机上会被系统压成 4 格宽**(系统按桌面网格算),它的价值在平板/折叠屏。


## 0.3.4 更新:数据地基(备份 / 恢复 / 每日快照)

这一版不改变界面主流程,只给数据加了一层保险 —— 从此换手机、误删、误恢复都有回头路。

### 怎么用
设置(右上角 ⚙)→「数据备份」四颗按钮:

| 按钮 | 作用 |
|---|---|
| **导出备份** | 存成一个 `.json` 文件(约 9 KB),系统文件选择器让你选位置(下载/网盘/微信) |
| **从备份恢复** | 选一个之前导出的 `.json`,确认后**整体覆盖**当前数据 |
| **立即快照** | 立刻在手机本地存一份快照(平时每天首次打开也会自动存一份) |
| **恢复快照(N)** | 列出本机最近 7 份快照(带「今天 / 昨天 / 日期 + 时间」和「N 门课 · M 条任务」),点「恢复」回到那一刻 |

### 安全设计(为什么不会把数据搞丢)
- **恢复前先自保**:不管是导入 json 还是恢复快照,都会先把**当前状态**存一份快照,再覆盖。
  所以「手滑恢复错了」还能再退回来(toast 会提示「旧数据已存快照」)。
- **快照只留最近 7 份**,按时间倒序自动清旧,不会无限占空间。
- **每天首次打开自动存一份**:距上次超过 20 小时才会真的写,不会每次开 App 都写盘。
- **导出的 json 是纯文本**,里面写明 `app/format/versionName/时间` +
  课表/任务/排序/开学日期/周数/城市/主题/折叠状态;恢复时会校验是不是本 App 的文件。
- **排序也一起备份**:课程分组顺序按课程名存,支线顺序按 uuid 存(内部 id 跨设备会变,uuid 不会)。

### 底层改动(为后面的同步铺路)
- 数据库版本 **v1 → v2**,`courses` / `tasks` 两张表都新增 `uuid`(稳定的全局标识)和 `updatedAt`(最后修改时间)。
- 迁移用的是**重建表 + 搬数据**(而不是加带默认值的列),保证新旧 schema 与 Room 期望完全一致;
  老数据全部保留,并自动补上新字段(实测:18 门课 + 7 条任务原样迁过来)。
- 现在还没有 `deleted` 墓碑字段 —— 等真做云同步时再加 v2→v3。

## 0.3.2 更新:三处按反馈修正

### 1. 课程标题不再有暗色底条
0.3.1 给分组标题加的那条淡底色(`cellLine` 40%)去掉了,标题行回到面板本身的底色上;
教师名也回到更淡的 `ink3`。现在只有 16dp 的分组间距在分隔各块,不再有"糊了一层灰"的感觉。

### 2. 被挤走的那一项现在会滑过去,而不是直接弹到位
根因:邻居的位移动画状态是**按位置**记住的,一旦换位,那个状态被重建 → 位移直接归零,
看起来就是"啪"地跳到新位置;而且旧写法把"钉住原位"放进协程里,还要晚一帧才生效,也会闪一下。
现在:
- 位移状态按 **id/课程名** 常驻,换位不重建;
- 换位瞬间**同步**把邻居钉在原位,再用弹簧收尾滑到新槽位(约 300ms);
- 松手时拖拽项也是同步接住当前位置再弹回,不再先跳一格再弹。

### 3. 拖拽时的白色乱字/闪烁:再清一遍
0.3.1 只解决了"半透明卡片透出下层文字",这次把剩下两个诱因也去掉:
- **取消了拖动时的放大(1.012×)**:缩放会让文字在拖动过程中不断重新栅格化,
  在这种 ROM/GPU 上会闪出残缺字形(看起来就是白色乱码)。现在只抬阴影,不动缩放。
- **抬升阴影从"增删修饰符"改成"常驻图层里改属性"**:拖动项在拖动开始/结束那一刻
  不再新增或移除 `shadow(...)` 节点(节点增删会掉帧、甚至闪出上一帧残影),
  位移、阴影、圆角全部落在同一个常驻 `graphicsLayer` 上,只改数值。
- 拖动项依旧使用**不透明底色**(面板色叠在背景色上算出来的实色),下层文字透不上来。

课程作业与支线任务两处都按同一套改,行为一致。

### 现在的操作方式(课程作业 / 支线任务统一)
- **课程作业**:拖分组标题左侧的**三点握把**(或长按标题行)上下拖;
- **支线任务**:拖卡片左侧的**三点握把**上下拖;
- **向上/向下都能一直拖**,不限一位;越过相邻项中心距(≈重合 50%)即换位;
- 拖起来的那一块只做**投影抬升**(不缩放),邻居让位是**弹簧滑动**;
- **置顶的任务不参与拖动**,始终排在最前(所以它不显示握把);
- 拿起 / 每次换位有一格轻微震动;
- 原来的「⠿ 上移一位 / 下移一位」菜单已移除,排序只走拖动。

### 数据不动
0.3.2 没有改数据库结构(仍是 Room v1),顺序仍是本地偏好里的一份字符串。
从 0.3.0 起一路覆盖安装实测:18 门课 + 8 条任务 + 排好的顺序都在;
杀进程重启后顺序依旧(排序是"内存立刻生效 + 落盘异步合并",连续快速拖动也不丢格)。

## 关于「为什么更新会毁掉手机上的数据」

核对过代码,更新本身不会动数据,真正的坑有三个(都不在「更新」,而在更新的附带动作):

1. **签名不一致 → 只能卸载重装(最可能的原因)**:如果打包用的 keystore 变了
   (换机器、换 IDE、删了 `.android/debug.keystore`),Android 会直接拒绝覆盖安装并报
   `INSTALL_FAILED_UPDATE_INCOMPATIBLE`。唯一的"解决办法"就是先卸载——而卸载会连
   `/data/data/com.campusquest.app` 整个删掉,数据库和偏好一起没。
   **对策:签名 keystore 已进版本库并写死在 `app/build.gradle.kts`。**
2. **Room 升版本却没写 Migration**:`Db.kt` 里 `version = 1`,没有 Migration、
   也没有 `fallbackToDestructiveMigration`。哪天把版本号 +1 而不写迁移,App 会一启动就崩。
   **对策:规则已定死——动表结构必须先写 Migration,否则不许动版本号。**
3. **重新导入课表会先清空 courses 表**:`applyImported` 是「先 clear 再 insert」,
   误触导入 = 课程表被替换(任务不受影响)。
   **对策:下一步做「导出/导入 JSON 备份 + 每日自动快照」(路线图 D3),让手机里永远有一份可恢复的数据。**
