CampusQuest · 桌面小组件雏形

0.4.0 的提案稿,先看设计再写进 APK。六种尺寸从最小到最大(2×1 → 5×4), 统一原则:待办优先(逾期 → 今天 → 48 小时内 → 其余,置顶插队),课表作为第二信息层。 配色、圆角、噪点、字重沿用 App 的设计基线,深浅色都跟随系统/时间。

1 dp = 3 px 绘制 · 手机约 393dp 宽,所以 4 列 = 250dp ≈ 屏宽的 2/3
① 极简条2×1 · 110×40dp最小

只放一件:最急的那件。桌面很挤时的默认尺寸。

  • 数据:排序后第一条未完成待办;没有待办时显示「今天没有待办」,点一下直接开「支线」页。
  • 点击:左勾选框 = 完成(带 450ms 撤销?不做,直接完成 + 触感);其余区域 = 打开 App。
  • Glance 落地:纯文字 + 形状,零妥协。

三种尺寸的空态 / 边界同样重要

小组件最容易崩在「没有数据」的时候,所以先把空态画出来。

今天没有待办
今天没有待办 ✓
今天没课了
  • 空态不写「暂无数据」,写成人话:「今天没有待办 ✓」/「今天没课了」,语气跟 App 里的空态一致。
  • 未开学 / 已放假:课表区显示「第 7 周还没开始」;待办区照常工作(支线任务跟学期无关)。
  • 更新节奏:每 15 分钟一次 + 完成/新增后主动刷新;倒计时文案精确到分钟,和列表里的胶囊一致(剩 1 天 6 小时)。

说明:只有 ①③ 是真正「便宜」的(2×1、4×1,纯文字,Glance 一天能写完); ②④⑤⑥ 需要处理圆角 drawable、分组背景、深色适配与长标题截断,预计 3–5 天。 全部尺寸共用同一套数据层(Backup 已有的导出结构反过来就是小组件的读模型),不需要重复取数逻辑。
